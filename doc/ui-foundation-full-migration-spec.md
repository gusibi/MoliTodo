# MoliTodo UI Foundation：全应用迁移 Spec

日期：2026-09-20  
状态：实施草案，尚未开始实现  
前置文档：[Today 首轮试点 Spec](./ui-foundation-spec.md)  
交付形式：本地文档，不创建 GitHub issue

## Problem Statement

Today 试点只能验证一组基础规则，不能解决整个应用中按钮、字体、图标、任务状态、弹层和主题行为分散的问题。用户在列表、看板、日历、编辑器、设置和悬浮窗口之间切换时，仍可能遇到同类操作不同尺寸、不同确认方式、信息层级不一致或离线图标缺失。

开发维护也缺少稳定边界：新页面容易再次实现按钮和弹层，主题 CSS 可能重新定义组件外观，第三方日历和自建控件缺少共同的视觉规则。仅扩大局部 CSS 修改无法持续解决这些问题。

本项目需要将 Today 中验证有效的基础组件与交互规则推广到所有实际使用的桌面界面，在保留现有任务业务和平台窗口特性的同时，建立可复用、可测试、可逐步维护的 UI 基础层。

## Solution

保留 Vue、Tailwind 3、现有主题机制及应用分层。采用兼容版本的 shadcn-vue 组件源码、Reka UI 交互原语、本地 Lucide 图标和系统字体，分阶段统一基础组件、任务展示、主窗口结构、设置与悬浮窗口。

迁移完成后，用户应能在所有活跃界面中识别一致的按钮、输入、状态和确认交互；图标无需网络加载；五套主题使用同一组件规则；键盘、焦点和弹层行为在不同窗口中保持可靠。

本 Spec 是完整迁移的目标与验收契约，不要求一次性实现。Today Spec 作为阶段 0 保留；其仅限试点的作用域、暂留 CDN 等限制，在相应迁移阶段完成后解除。其他既有业务约束继续有效。

### 全量覆盖清单

| 区域 | 本轮全量目标 | 必须保持的行为 |
| --- | --- | --- |
| 主窗口外壳 | Sidebar、Header、Content、Inspector 的背景、分隔线、按钮、间距 | 平台标题栏、窗口拖动、尺寸适配、导航和搜索 |
| Today | 将试点接入全局共享规范，移除不再需要的临时变体 | Agenda 分组、Future Calendar、窄窗口抽屉、计数与编辑联动 |
| 普通任务列表 | 列表控件、任务行、分组、多选、批量操作、快速输入 | 筛选、排序、拖拽、状态切换和现有提交方式 |
| 看板 | 列头、任务卡、添加入口、状态和元信息 | 跨列拖拽、状态迁移和现有排序规则 |
| 日历 | 周视图、月视图、日期导航、任务事件和筛选 | 日期语义、任务定位、已有拖拽或编辑能力 |
| Inspector | 标题、表单、描述、步骤、时间、重复规则、删除入口 | 保存、取消、现有自动保存或失焦提交语义 |
| 清单管理 | Sidebar 清单项、创建编辑、图标颜色选择、已有菜单 | 清单数据、选中状态及任务归属 |
| 业务弹窗 | 预览、详情、任务选择、报告以及其他活跃弹窗 | 原有业务内容、选择结果和操作后果 |
| 设置 | 通用、外观、提醒、浮标、AI、API 服务、数据、统计、关于 | 配置读写、校验、连接行为、数据操作及重启持久化 |
| 悬浮界面 | 悬浮图标中的 UI 控件、任务面板、单任务悬浮窗口 | 显示隐藏、置顶、拖动、鼠标穿透和窗口间任务同步 |
| 统计图表 | 字体、主题色、图例、提示和容器 | 原有统计计算与数据含义 |

“全量”以路由、导入关系和运行入口实际可达的界面为准。目录名称本身不是可达性的证据；未使用组件不为完成覆盖率而迁移或删除。官方网站不属于本 Spec。

## User Stories

1. As a MoliTodo 用户, I want 不同页面的同类按钮具有一致的含义和反馈, so that 我不必重新学习操作方式。
2. As a MoliTodo 用户, I want 侧边栏清楚显示当前页面与清单, so that 我随时知道自己在哪里。
3. As a MoliTodo 用户, I want 主窗口通过背景与分隔线组织内容, so that 页面层级清楚且不过度堆叠卡片。
4. As a MoliTodo 用户, I want 任务正文始终比辅助信息更醒目, so that 我能快速浏览和选择任务。
5. As a MoliTodo 用户, I want 相同任务状态在列表、看板和日历中含义一致, so that 切换视图不会产生误解。
6. As a MoliTodo 用户, I want 提醒、安排、截止和计时超时保持区别, so that 我能作出正确的时间判断。
7. As a MoliTodo 用户, I want 元信息简洁但不遗漏业务信息, so that 我能在紧凑界面中理解任务。
8. As a MoliTodo 用户, I want 快速输入和任务编辑保持现有提交习惯, so that 外观升级不打断工作流。
9. As a MoliTodo 用户, I want 批量选择状态和批量删除数量明确, so that 我不会误删未选中的任务。
10. As a MoliTodo 用户, I want 拖拽任务时目标和反馈清楚, so that 我能可靠地调整任务位置或状态。
11. As a MoliTodo 用户, I want Inspector 的表单、步骤和时间操作一致, so that 编辑复杂任务更容易。
12. As a MoliTodo 用户, I want 不同日期选择器具有一致的外观与关闭行为, so that 我能顺畅填写时间。
13. As a MoliTodo 用户, I want 编辑清单后原有图标和颜色仍能识别, so that 升级不会破坏个人组织方式。
14. As a MoliTodo 用户, I want 删除任务、步骤、批量项目和清空数据前看到准确说明, so that 我能理解操作后果。
15. As a MoliTodo 用户, I want 取消确认不会修改数据, so that 我可以安全退出误操作。
16. As a MoliTodo 用户, I want 危险操作进行中有明确反馈且不会重复提交, so that 我知道应该等待。
17. As a MoliTodo 用户, I want 操作失败后仍保留必要输入并能重试, so that 我无需重新开始。
18. As a 键盘用户, I want 所有按钮和菜单能被定位与操作, so that 我不依赖鼠标。
19. As a 键盘用户, I want 弹层按正确顺序关闭并恢复焦点, so that 我能继续原来的操作。
20. As a 辅助技术用户, I want 控件提供明确名称、状态与错误信息, so that 我能理解当前界面。
21. As a MoliTodo 用户, I want 悬停出现的操作也能通过键盘发现, so that 精简外观不减少可用性。
22. As a MoliTodo 用户, I want 五套主题及明暗模式保留个人偏好, so that 我无需在升级后重新配置。
23. As a MoliTodo 用户, I want 不同窗口的主题保持同步, so that 应用看起来一致。
24. As a 离线用户, I want 所有核心 UI 图标无需联网显示, so that 应用的操作入口不会缺失。
25. As a Windows 用户, I want 字体、背景和窗口按钮适合 Windows, so that 界面不会因偏向 macOS 而退化。
26. As a macOS 用户, I want 现有窗口材质与拖动行为保持正常, so that 应用仍适合桌面使用。
27. As a 悬浮面板用户, I want 操作菜单或弹窗时窗口不会意外隐藏, so that 我能完成任务操作。
28. As a 悬浮任务用户, I want 操作结果与主窗口同步, so that 我不会看到互相矛盾的任务状态。
29. As a 设置用户, I want 开关、选择器和错误提示保持一致, so that 我能可靠地调整配置。
30. As a 统计用户, I want 图表在不同主题中仍清晰且不改变数据含义, so that 我能准确阅读进度。
31. As a MoliTodo 用户, I want 长文本、中英文和窄窗口都不遮挡关键操作, so that 我能在自己的使用环境中工作。
32. As a 减少动态效果的用户, I want 所有新增动效尊重系统偏好, so that 界面变化不会造成干扰。
33. As a MoliTodo 维护者, I want 新页面复用已有组件和语义 token, so that 后续 UI 不再逐页分化。
34. As a MoliTodo 维护者, I want 每个迁移阶段独立可验证, so that 我能发现回归并控制发布范围。

## Implementation Decisions

### 1. 架构和依赖

- 延续阶段 0 已验证的 Vue、Tailwind 3、shadcn-vue、Reka UI 与 Lucide 组合，记录确切安装版本。若阶段 0 尚未实施，先完成兼容性验证，不将文档中的选型视为验证结果。
- 不使用 React 版 shadcn 安装流程，不直接覆盖现有主题入口或构建配置，不夹带工具链大版本升级。
- 基础组件处理语义、键盘、焦点、视觉状态；业务组件组合这些能力；应用服务继续负责数据行为。UI 组件不直接访问 SQLite 或新增业务 IPC。
- 不为每种页面建立组件副本。允许有实际用途的紧凑与常规尺寸，避免任意尺寸参数扩散。
- 保留现有应用状态管理、数据格式和国际化机制。新增文案提供项目现有语言版本，不在组件内部新增硬编码业务文案。

### 2. 基础组件契约

| 组件类别 | 能力与约束 |
| --- | --- |
| Button / IconButton | 默认、强调、弱化、危险等实际所需变体；尺寸、禁用、加载、焦点统一；图标按钮有名称 |
| Checkbox / Switch | 值与事件明确；多选支持需要的半选状态；Switch 用于设置开关，完成任务保持任务语义 |
| Input / Textarea | 标签、描述、错误、禁用、只读与焦点规则统一；保留现有输入及提交行为 |
| Select / DropdownMenu | 区分选择值与执行动作；键盘导航、关闭和焦点恢复统一 |
| Tooltip / Popover | 区分非交互说明与交互内容；Tooltip 不能承载必须点击的按钮或唯一的操作说明 |
| Dialog / AlertDialog | 普通编辑与危险确认职责分开；支持标题说明、焦点约束、异步状态和恢复 |
| Badge / Separator | 用于实际语义和分隔，不能把所有辅助文本重新包装成彩色标签 |
| Sheet / 其他布局组件 | 仅在现有抽屉等场景确实需要时引入；不因组件库提供就增加功能 |

- 基础组件数量由活跃页面实际需要决定。Resizable、ScrollArea、Calendar 等不作为默认必装项；保留原生滚动和现有成熟日历能力。
- 为组件保留简明的使用说明与状态样例，覆盖常见组合和不适用场景。无需建立独立展示站。
- 新增或迁移区域禁止重新实现已经提供的基础交互；第三方库内部控件通过适配样式处理，不强制改写其 DOM。

### 3. Design Tokens 与主题

- 保留现有语义颜色体系，补齐实际使用的正文层级、行高、控件高度、图标尺寸、间距、圆角、浮层阴影和动效规则。
- 明确 token 到 Tailwind 与组件的映射，尤其是多个圆角档位、阴影和带透明度的颜色用法；新增变量必须有实际消费者。
- 系统字体作为默认字体策略，兼顾 macOS、Windows 和中文回退；去除对未打包字体的隐式依赖。不要求不同平台像素完全一致。
- 五套主题共享布局与交互，只覆盖允许的 palette、surface contrast、radius、elevation 等外观 token；主题不通过页面选择器重新设计组件。
- 保留用户已有主题 ID、选择和明暗偏好，验证持久化及跨窗口同步。迁移期间旧 token 可暂时映射到新值，所有消费者迁移后再移除本次替代的别名。
- 整理主题的顺序可以在后期，但每个迁移阶段都必须验证其他主题，不能把可读性回归留到最后。
- 普通正文对比度目标至少 4.5:1，必要控件边界和焦点指示至少 3:1；不能仅靠颜色传达状态或错误。

### 4. 图标与历史数据兼容

- 将所有活跃渲染路径上的 Font Awesome、字体图标及同类临时 UI 图标迁移为本地 SVG 组件；统一尺寸、描边和对齐。
- 不替换应用品牌 Logo、系统托盘或安装包图标资产。这些资产有独立平台用途。
- 清单图标存在持久化名称，提供有限的显式旧名称到新图标映射。保持已有数据可读，不为图标更换重写用户数据库。
- 未识别名称使用可辨认的默认清单图标，不崩溃，不自动改写原值。图标选择器和展示使用同一语义映射。
- 禁止为了动态名称导入整套图标；只打包映射中实际使用的集合。
- 完成活跃调用与生成内容检查后移除 Font Awesome CDN、相关字体依赖和确已失去消费者的样式。冷启动离线验证不能依赖浏览器缓存。
- 图表和第三方日历产生的图标也纳入审计；可保留库自身本地 SVG 或 CSS 绘制的必要控件，不要求每个图形都来自 Lucide。

### 5. 主窗口 Surface 与导航

- Window、Sidebar、Content、Header 与 Inspector 主要依靠背景层次和细分隔线区分。降低主内容大卡片的外边距与阴影，先用真实界面截图确认效果。
- 阴影主要用于真正覆盖内容的 Popover、Dropdown、Dialog 和 Context Menu；任务卡可因视图语义保留边框或轻量表面差异。
- 调整主内容边距时同步修改依赖该边距的宽高计算，避免布局溢出或空白；不能仅删除圆角和阴影类就宣布完成。
- 保留 Windows 的不透明背景处理、macOS 的现有材质以及标题栏安全区域。窗口拖动区域不能覆盖可点击按钮。
- Sidebar 的选中、悬停、焦点、计数和清单色标规则统一；应用导航使用合适的导航语义，不为视觉效果强行改成复杂菜单。
- 统一 Header 的搜索、筛选、视图切换和图标按钮，保留现有键盘快捷方式与交互结果。

### 6. 任务展示与 Inspector

- 以 Today 试点的正文、元信息与操作规范作为起点，推广至列表、看板和日历；不强迫三种视图使用相同尺寸或完全相同 DOM。
- 同一业务状态使用相同语义颜色与名称；完成、暂停、进行中、截止逾期和计时超时仍沿用原模型。
- Hover 操作同时支持键盘焦点及菜单展开状态；显示操作不挤动正文，主要入口不因精简外观而难以发现。
- 保留排序、分组、搜索高亮、拖拽、多选、批量动作及虚拟重复实例行为。任务状态变化仍通过既有业务链更新其他视图。
- Inspector 统一表单、描述、步骤、提醒、时间和重复选择器的外观与语义；保持现有保存、取消、自动保存及校验规则，不改为新的表单提交模型。
- 日期字段的解析、时区、全天日期、提醒、安排和截止关系保持不变。视觉适配不能把日期型值隐式转换为午夜时间戳。

### 7. Overlay 与危险操作

- 统一浮层 surface、border、elevation、层级和动效；复用 Reka 的交互原语。只有真实业务需要时才新增共享协调状态，不预建通用弹层管理框架。
- Tooltip 非模态；Dropdown 与普通 Popover 按场景关闭；编辑 Dialog 的遮罩和未保存内容行为沿用现有业务要求。不能用同一关闭规则粗暴覆盖所有浮层。
- 嵌套日期选择器或菜单应属于所在 Dialog 的交互范围。Escape 优先关闭最上层，关闭后恢复到合理触发点，不穿透触发背景操作。
- 将所有活跃渲染路径中的原生 confirm 迁移到统一 AlertDialog，包括任务、步骤、批量删除、清空数据和重置设置。现有自建确认框同样收敛到这一组件。
- 操作对象、数量、影响范围、是否可恢复必须与实际业务一致。不能把清空数据表述为仅清空当前清单，也不能暗示不存在的撤销能力。
- 延续 Today 的确认契约：初始焦点为取消；等待及失败时 Escape 可退出；遮罩点击不确认；提交中防重复并阻止产生取消成功的错觉；失败保留上下文并提供重试。
- 成功后的焦点返回有效位置；被删控件不存在时移动到相邻对象或当前区域的合理入口。列表批量删除、清空数据等场景分别定义落点。
- 现有业务 alert 若需随区域迁移，使用项目统一反馈方式；prompt 若存在则使用有标签和校验的输入 Dialog。实施前盘点实际调用，不虚构必须新增的通知系统。
- 保留系统文件选择、目录选择和操作系统权限提示；这些不属于要消除的原生业务 confirm。

### 8. 日期组件、设置和图表

- FullCalendar、v-calendar、Vue Datepicker 暂保留各自业务职责，适配其主题、输入、导航、选择状态和弹出表面，不在本项目中重写日期算法。
- 明确第三方 portal/teleport 的主题继承与层级归属；避免依赖容易变化的内部 DOM 选择器，优先使用公开配置与 CSS 变量。
- 设置统一字段标签、帮助文字、错误、Switch、选择器和操作区；不得因展示统一而改变配置生效时机。
- AI、API 与数据设置保留现有连接、服务、导入导出和校验行为，错误提示不丢失可行动信息；测试使用隔离配置，不读取或输出真实密钥。
- 图表接入主题字体、颜色与提示规则，保留可辨认的数据系列；不得为降低颜色数量而改变统计含义或把必要数据系列隐藏。

### 9. 多窗口与悬浮界面

- 悬浮界面可以采用更紧凑尺寸，但共享相同状态语义、焦点规则和图标体系，不为紧凑布局恢复难以点击的操作区域。
- 每个 BrowserWindow 使用自己的浮层根和主题状态；DOM Portal 无法越过原生窗口边界，不设计跨窗口 DOM 弹层。
- 按窗口可用尺寸处理菜单和弹窗定位。必要时在现有窗口管理边界内临时调整尺寸或把操作交给明确的主窗口入口，具体方案实施时以真实 Electron 验证决定并记录。
- 打开交互浮层时，现有鼠标移出隐藏逻辑不得中断操作；关闭或完成后恢复原策略。只对确实受影响的窗口逻辑做窄范围调整。
- 验证鼠标穿透、置顶、拖动、窗口关闭及多窗口同步；不引入整个应用新的窗口生命周期模型。

### 10. 分阶段交付与清理

| 阶段 | 交付范围 | 阶段完成门槛 |
| --- | --- | --- |
| 0 | Today 试点 | 前置 Spec 验收通过，依赖及视觉规则已记录 |
| 1 | 共享基础组件、token 映射、Sidebar 与 Header | 导航与搜索无回归，其他主题可读，组件能被第二个区域复用 |
| 2 | 全部任务展示、Inspector、清单管理 | 各视图任务操作和数据同步保持一致，旧图标数据兼容 |
| 3 | 全部业务弹层、日期适配、设置和统计 | 原生业务确认迁移完成，焦点与危险操作矩阵通过 |
| 4 | 悬浮界面、跨窗口主题和交互 | 真正 Electron 窗口行为通过，紧凑尺寸不截断操作 |
| 5 | 主窗口 Surface 定稿、主题收敛、CDN 与重复样式清理 | 全覆盖清单完成，离线冷启动与平台验收通过 |

- 阶段可按依赖合理拆分，但每阶段只迁移完整用户流程，不交付“按钮换了、弹窗无法使用”的中间状态。
- 主窗口布局可先制作可回退的局部改动，在阶段 5 完成跨平台视觉确认；不要在基础组件尚未稳定时同时重做所有布局。
- 每阶段记录已迁移调用方、未迁移调用方、验证结果和临时兼容项。全部调用迁移后移除试点专用变体和本次产生的重复实现。
- 不顺手删除历史 unused 目录或修复无关问题。独立迁移提交便于回退，但本 Spec 不授权执行提交、发布或部署。

## Testing Decisions

### 主要测试入口与原则

- 建议继续使用已有 Playwright Electron fixture 作为全量迁移的主要测试入口，扩展页面与窗口覆盖，复用真实渲染层、IPC、应用服务和隔离 SQLite 数据；此方案由 Today 测试建议扩展，尚未作为用户已确认的决定。
- 沿用串行执行、独立临时用户目录、失败 trace 与截图。数据清空和重置测试必须使用一次性数据库及设置目录。
- 验证用户看到的状态、键盘行为与持久化结果，不为每个 CSS 类、DOM 包装或组件内部状态编写测试。
- 复用已有 Today 的分组、完成、编辑、日期、抽屉、焦点恢复和持久化测试；新增区域优先在同一 fixture 中补场景，不为每页建立独立 mock 框架。
- 对异步失败和重复提交，优先在已有服务边界进行局部失败注入；仅确有覆盖收益时增加基础组件交互测试。不得增加生产测试后门。

### 行为验收矩阵

| 流程 | 必须验证的结果 |
| --- | --- |
| 导航与搜索 | 活跃项、筛选和搜索结果正确；键盘可达；切换页面不丢失既有状态 |
| 列表与 Today | 新建、完成、取消完成、计时状态、编辑、选择与拖拽行为保持；计数及日历同步 |
| 看板与日历 | 保留现有跨列/日期操作、排序、日期语义与保存结果 |
| Inspector | 文本、步骤、时间、提醒和重复设置保存正确，取消与校验不退化 |
| 清单图标 | 旧名称、未知名称、新选择和重启后展示正常；无数据改写要求 |
| 危险操作 | 每种业务至少验证目标正确、取消无副作用、确认持久化；共享确认机制覆盖重复提交、失败、重试和焦点 |
| 批量删除 | 显示准确数量，只删除选中对象；删除后选择和焦点有效 |
| 清空及重置 | 对应数据或设置按现有约定变化；取消保持原状；不操作真实用户目录 |
| 嵌套弹层 | 日期选择、菜单与 Dialog 可同时正确工作；Escape 顺序正确，背景不误触 |
| 设置 | 开关与选择器值正确、错误可理解、重启持久化；不产生真实外部副作用 |
| 悬浮窗口 | 显示隐藏、鼠标穿透、置顶、拖动正常；浮层不意外消失；任务状态跨窗口同步 |
| 主题 | 五套主题的明暗切换与持久化、跨窗口同步、对比度和焦点可见性 |
| 离线 | 禁止外部网络并使用干净缓存冷启动，所有活跃核心 UI 图标可见，无字体图标 CDN 请求 |

### 视觉与平台验证

- 每阶段保留同任务数据、同窗口尺寸的前后截图；先确认任务正文、信息层级、点击区域与布局，再判断风格是否一致。
- 全部主要区域检查默认主题明暗模式；五套主题的明暗组合至少覆盖任务行、表单、危险确认、日期选择器、图表和悬浮面板，采用代表性页面避免机械生成全排列截图。
- 覆盖长中文、长英文、窄窗口、空状态、加载、错误、禁用、悬停、焦点和提交中状态；没有现成业务状态的地方不为测试新增功能。
- 在 macOS 与 Windows 的实际可用环境中验证窗口材质、标题栏、缩放和悬浮行为；Linux 若没有既有支持承诺，不因本 Spec 扩展支持范围。
- 使用键盘和针对性的辅助功能检查验证标签、语义、焦点顺序、控件名称及颜色对比。库提供基础能力不等于应用自动满足无障碍要求。
- 动效尊重 prefers-reduced-motion，不为普通控件增加持续动画；交互不因视觉过渡而阻塞。
- 对大量任务的列表、看板和日历做改前改后的代表性操作比较；若出现明显卡顿或包体异常增长，定位图标全量导入或每行重复创建浮层等原因。不开启无关性能重构。

### 最终完成标准

1. 全量覆盖清单中所有实际活跃界面均已迁移，例外有明确原因且不破坏用户流程。
2. 活跃业务代码不再使用原生 confirm；系统文件与权限对话框按用途保留。
3. 核心 UI 图标本地可用，旧清单图标数据兼容，移除 Font Awesome CDN 及已失去用途的资源。
4. 五套主题继承同一基础组件规则，主题切换与跨窗口表现通过检查。
5. renderer 构建、相关现有单元测试和完整 Electron E2E 通过；补充场景覆盖本轮行为变化。
6. 任务、日期、重复规则、数据及设置无已知回归；平台检查和视觉证据记录齐全。
7. 若某个平台或检查无法执行，明确列为未验证项，不声明全平台完成；继续完成可执行部分。
8. 基础组件使用说明、token 规则与临时兼容项清理记录更新，后续开发有明确复用入口。

## Out of Scope

- 改变任务模型、时间语义、重复任务生成、统计算法、提醒调度或数据库结构。
- 全量改用其他 UI 框架、替换全部日历依赖、升级 Tailwind 4 或 Electron/Vite 大版本。
- 新增撤销删除、全新快捷键体系、命令面板、云同步、任务状态或其他产品功能。
- 重做品牌 Logo、安装包、托盘图标与官方网站。
- 强求 macOS 与 Windows 像素一致，或抹去已有的平台特性。
- 整理无关死代码、改写所有测试选择器、建立完整独立组件展示站。
- 本次文档请求不包含 UI 实现、提交、创建 GitHub issue、发布或部署。
