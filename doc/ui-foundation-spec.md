# MoliTodo UI Foundation：Today 任务行首轮试点

日期：2026-09-20  
状态：实施草案；测试入口方案已提出，等待用户反馈  
交付形式：本地 Spec，不创建 GitHub issue

后续完整范围见 [全应用迁移 Spec](./ui-foundation-full-migration-spec.md)。本文保留为阶段 0，可独立实施与验收。

## Problem Statement

MoliTodo 已有主题变量和组件样式，但按钮、任务元信息、图标和确认弹窗缺少一致的使用规则。用户在同一条任务中会看到多个视觉权重相近的状态提示，而真正重要的任务内容较小；部分操作按钮点击区域过矮，删除时又切换到原生确认框。

当前渲染层依赖网络加载 Font Awesome，声明的部分字体也没有随应用提供，导致离线和不同系统环境下的外观缺少可控性。

本轮要验证：在保留现有任务业务和页面布局的前提下，通过一个完整的 Today 任务行与删除交互试点，是否能改善内容层级、操作一致性和键盘可用性，并形成能继续复用的基础组件。

本 Spec 以当前本地实现为基线，包含 Today 的 Agenda、Future Calendar、窄窗口日历抽屉和任务编辑面板，不沿用原分析报告中的旧 main 提交作为实施基线。

## Solution

保留 Vue、Tailwind 3 和现有主题机制，以 shadcn-vue 的兼容版本作为基础组件源码起点，使用 Reka UI 处理确认弹窗的焦点与交互，使用本地打包的 Lucide SVG 图标改善试点区域的一致性。

本次交付限定为 Today 中现有任务行呈现、所需基础按钮和任务删除确认流程。先把任务正文、元信息、点击区域及弹窗体验作为整体验证，再决定后续区域迁移。

试点覆盖 Today 内各分组复用的同一种任务行组件及其现有状态，不新增任务类型、不改变分组规则。默认主题用于确定视觉方案；其他已有主题及明暗模式必须保持可读、可操作。

## User Stories

1. As a MoliTodo 用户, I want 先看清任务正文, so that 我能快速判断下一步要做什么。
2. As a MoliTodo 用户, I want 描述和时间信息形成清晰的次级层级, so that 它们提供上下文而不抢占正文注意力。
3. As a MoliTodo 用户, I want 正在进行和真正截止逾期的任务仍然容易识别, so that 我能及时处理重要状态。
4. As a MoliTodo 用户, I want 过去安排、截止逾期和计时超时保持各自含义, so that 我不会误读任务的紧急程度。
5. As a MoliTodo 用户, I want 重复、提醒和耗时信息保持可见且不过度装饰, so that 我能在紧凑界面中理解任务。
6. As a MoliTodo 用户, I want 常用操作具有稳定且足够的点击区域, so that 我不容易误触相邻操作。
7. As a MoliTodo 用户, I want 操作按钮出现时不挤动正文, so that 我可以持续阅读和点击。
8. As a 键盘用户, I want 在任务行获得焦点时发现并使用其操作, so that 我不依赖鼠标悬停。
9. As a 键盘用户, I want 焦点位置始终清楚, so that 我知道当前操作会影响哪个控件。
10. As a 辅助技术用户, I want 图标按钮和勾选控件具有明确名称与状态, so that 我能理解并执行操作。
11. As a MoliTodo 用户, I want 删除前看到与当前主题一致的确认弹窗, so that 我能确认目标和删除后果。
12. As a MoliTodo 用户, I want 取消删除或按 Escape 后任务保持不变, so that 我能安全退出误操作。
13. As a MoliTodo 用户, I want 删除处理中重复点击不会重复提交, so that 操作结果稳定。
14. As a MoliTodo 用户, I want 删除失败时看到原因并能重试或退出, so that 我不会误以为任务已删除。
15. As a 键盘用户, I want 关闭弹窗后焦点回到合理位置, so that 我可以继续管理任务。
16. As a MoliTodo 用户, I want 完成、取消完成和编辑继续更新分组、计数与日历点, so that 外观升级不破坏已有工作流。
17. As a MoliTodo 用户, I want 在窄窗口、长标题和中英文界面下仍可操作任务, so that 我不必放大窗口才能完成工作。
18. As a 离线用户, I want 本轮迁移区域的图标无需网络即可显示, so that 核心操作仍然可辨认。
19. As a 主题用户, I want 试点在所有已有主题及明暗模式中保持可读, so that 我能继续使用自己的外观偏好。
20. As a 减少动态效果的用户, I want 弹窗和任务行尊重系统偏好, so that 动画不会妨碍使用。

## Implementation Decisions

### 1. 技术与范围

- 保留 Electron、Vue、Vite、Tailwind 3、Pinia 和现有主题加载机制，不借本轮升级整套工具链。
- 接入前验证 shadcn-vue 的 Tailwind 3 路线、Reka UI 与当前实际安装的 Vue/Vite 版本兼容性，固定经过构建验证的依赖组合。不得直接套用面向 Tailwind 4 的初始化配置。
- shadcn-vue 是可维护的组件源码起点，Reka UI 是底层交互依赖；组件落地后仍由项目维护。保持项目现有 JavaScript 风格，不要求全项目迁移 TypeScript。
- 首批提供 Button、IconButton、AlertDialog；Checkbox、Popover 仅在试点确实需要时增加。不得为了凑齐组件目录预建未使用组件。
- 不修改数据库结构、任务模型、IPC 契约、重复任务规则或状态机。UI 层继续调用现有应用行为。

### 2. 模块边界与共享组件

- 主要涉及 TodayOverview、AgendaTaskCard、FlatTaskItem、试点相关样式、基础组件、主题变量接入和本地化文案。
- 当前 AgendaTaskCard 复用 FlatTaskItem；改动前确认所有调用方。试点样式通过明确且有限的呈现变体或作用域限定到 Today，避免无意改变普通列表和其他窗口。
- 不复制一套任务状态、计时或删除业务逻辑。基础组件负责外观、语义和交互，页面负责选择任务和执行业务动作。
- 图标按钮复用按钮的尺寸、禁用与焦点规则，提供可访问名称；不创建跨项目通用配置框架。
- Today 已有的任务行删除入口和编辑面板删除入口统一进入同一确认流程；一次删除只弹一次确认框。其他页面暂时保留原行为。

### 3. 排版、尺寸与颜色

- 以任务正文 14px、次级描述 12px、元信息 11–12px 作为首版视觉基线；正文使用常规或中等字重，保证中文与长标题可读。此处是实施起点，最终数值以应用内验收记录为准。
- 任务行操作点击区域原则上不小于 28×28px，常规按钮以 32px 高为起点。Checkbox 的图形尺寸可以小于点击区域。
- 普通提醒、重复和耗时优先采用中性图标与文字。进行中、真正逾期、选中和危险动作保留强调，但不只通过颜色表达含义。
- 保留现有提醒、安排、截止和计时超时的领域含义；不将过去安排一律改为截止逾期。
- 将试点实际使用的字号、行高、控件尺寸、圆角和动效规则接入明确的共享样式或 token，不机械地为每个数值新增变量。
- 现有圆角配置只映射默认圆角；试点组件使用的其他圆角档位需要明确接入，不能假定修改单个变量会影响所有圆角类。
- 仅调整试点所需的 token 映射，避免全局覆盖导致未迁移区域发生意外变化。

### 4. 图标、字体与任务行交互

- 试点新增和替换图标使用本地打包的 Lucide Vue 组件，明确导入实际使用的图标，统一常用尺寸和描边规则。
- 旧区域尚未迁移前不移除 Font Awesome CDN；离线验收范围明确为本轮已迁移的控件，不宣称全应用图标已离线可用。
- 试点优先使用系统字体栈，同时保留适当中文回退；不依赖用户额外安装 Inter 或 Geist，不打包自定义字体。全局主题字体调整留给后续阶段。
- 次要操作可以在 hover、focus-within 或相关交互展开时显示；键盘聚焦的操作必须可见。显示与隐藏不能引起任务行宽度或正文位置跳动。
- 完成控件和正文入口保持易发现。不得用不可聚焦的视觉元素替代已有可操作控件。
- 长文本沿用明确的截断或换行策略，完整内容仍可通过现有编辑入口查看；不引入新的详情浏览方式。
- 现有拖拽、搜索高亮、状态操作与编辑入口继续有效，点击按钮不能意外触发行选择或编辑。

### 5. 删除确认契约

- AlertDialog 提供标题、说明、取消和危险确认动作；文案说明正在删除的任务以及现有删除行为的后果，使用现有国际化机制。
- 弹窗状态明确分为等待确认、提交中和失败。打开弹窗不执行删除，取消不修改任务。
- 默认焦点放在取消动作；Tab/Shift+Tab 在弹窗内循环，背景不接收交互。等待确认或失败状态下 Escape 取消，点击遮罩不触发删除且不关闭弹窗。
- 用户明确确认后调用现有删除动作。提交中禁止重复提交，并暂时禁止关闭或取消，避免制造已经撤销删除的假象。
- 成功后关闭弹窗并由现有数据流更新任务与相关视图；失败时保留弹窗，显示可理解的错误，恢复重试和取消能力。
- 取消后焦点返回触发控件；删除成功后若触发控件已移除，将焦点移到相邻可操作任务，无任务时回到 Agenda 的新建入口。
- 重复任务和虚拟实例沿用现有删除目标语义，不新增删除整个系列或未来实例的选择。没有删除入口的状态不因本轮自动获得入口。
- 弹窗渲染位置、主题继承和层级遵守当前应用结构；验证与已打开编辑面板、日期弹层的焦点和 Escape 行为。不得同时保留互相争抢焦点的模态层。

### 6. 主题与平台

- 默认主题先确定视觉基线，但 Default、Mint Green、Morandi、Twitter、Vercel 的明暗模式都要通过试点可读性检查。
- 不重做主窗口大卡片、侧边栏材质、Windows 不透明背景或 macOS 窗口效果。
- 共享组件接入不得改变悬浮窗口的鼠标穿透、显示隐藏或置顶行为；受影响时做针对性应用内回归。
- 保留现有窄窗口日历抽屉和编辑器布局，尊重 prefers-reduced-motion。

## Testing Decisions

### 测试入口

优先复用现有 Today Playwright Electron E2E 作为主要测试入口。它已经运行真实渲染层、IPC、应用服务和 SQLite，并通过真实 TaskService 预置任务，不需要另建浏览器专用业务 mock 层。

沿用每个测试独立用户数据目录与临时数据库、串行执行、失败保存 trace 和截图的做法。测试不得读写开发者真实任务数据。

测试入口方案已向用户提出，当前作为建议记录；未获得回复不视为确认，也不阻止交付这份本地草案。

### 测试原则与已有实践

- 测试用户可观察的行为和结果，不检查内部 ref、组件层级、某个 Tailwind 类或 token 名是否存在。
- 新测试优先使用角色、可访问名称和文本定位。只有确实没有合适语义入口时才增加稳定测试标识。
- 复用现有 Today 关于完成与取消完成、计数与日历点同步、编辑保存、窄窗口抽屉、Escape 焦点恢复、减少动态效果和重启持久化的测试实践。
- 单纯排版与图标调整采用应用截图和人工检查，不编写只复述 CSS 的测试。删除失败等难以稳定制造的场景，优先利用既有服务边界做局部失败注入并恢复；确有必要时才增加窄范围组件交互测试，不增加生产环境测试开关。

### 必须验证的外部行为

1. 鼠标与键盘都能完成、取消完成、打开编辑器和使用现有状态操作；正文、元信息与可见焦点保持清楚。
2. 从 Today 现有删除入口打开确认框，只出现一个弹窗；打开、取消、Escape 都不删除任务。
3. 弹窗焦点约束有效，取消返回触发控件；成功删除后焦点落到有效的后续位置。
4. 确认删除成功后任务消失，刷新后仍保持删除结果，相关计数和日历点按原规则更新。
5. 提交中重复激活不会重复执行业务动作；失败时任务仍存在，显示错误并可重试或取消。
6. 在编辑器或日期选择交互存在时，删除确认框的层级、关闭顺序和焦点恢复正确。
7. 试点图标在阻断外部网络请求后仍可见，且图标按钮名称可被辅助技术识别。
8. 长标题、中文和英文、空列表、多个元信息、窄窗口及五套主题明暗模式下不遮挡关键内容或操作；正文对比度目标为至少 4.5:1，必要控件边界与焦点指示至少 3:1。
9. 共享 FlatTaskItem 的非 Today 使用场景没有意外变化；既有拖拽和选择行为保持有效。

### 执行与完成条件

- 实施时运行 renderer 构建及 Today E2E；运行现有单元测试以检查任务规则回归。共享组件行为发生变化时，补充受影响页面的冒烟检查。
- 留存同一窗口尺寸、同一批任务数据下的改前改后截图，至少包含默认主题明暗模式、窄窗口和确认弹窗；其余主题使用精简视觉检查矩阵。
- 自动化断言通过后，在真实应用内检查点击区域、视觉层级和焦点流。macOS 与 Windows 分别验证可用的平台环境；没有执行的平台必须记录未验证项，不宣称已通过。
- 首轮完成标准：试点验收项通过，相关现有检查通过，无已知任务数据与交互回归，实施记录列明依赖版本、视觉调整与尚未验证的环境。
- 本文档的生成不代表上述实现或测试已经完成。

## Out of Scope

- 全应用 UI 重写，以及 Sidebar、Inspector、设置页、看板、月历、周视图的整体视觉改造。
- 一次性替换所有 Font Awesome 图标、删除全应用 CDN 依赖或全量修改字体。
- 一次性迁移所有原生 confirm，包括清空数据、重置设置、步骤删除和其他页面批量删除。
- 替换 FullCalendar、v-calendar 或 Vue Datepicker，或改变日历业务能力。
- Tailwind 4、Electron、Vite 等工具链大版本升级，以及全量 TypeScript 迁移。
- 全主题重设计、主窗口 Surface 布局重构、统一所有历史 CSS。
- 新增撤销删除、删除系列选项、任务业务状态或其他未讨论的功能。
- 新建独立组件展示站、通用弹窗服务框架、全应用视觉快照基础设施。
- 发布 GitHub issue、提交代码、发布版本或部署；本次请求只交付本地 Spec。

- 本方案依据当前代码检查和此前讨论整理，尚未进行视觉原型确认或依赖接入实验；若兼容性验证需要超出范围的工具链升级，应先记录具体阻碍和替代方案，再决定是否扩大范围。
