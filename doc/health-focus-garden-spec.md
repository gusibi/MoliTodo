| 项目 | 内容 |
| --- | --- |
| 版本 | v0.2 · 设计基线 |

实现基线：[领域词汇表](../CONTEXT.md) · [ADR-0001 工具域模块边界](../docs/adr/0001-tools-module-boundaries.md) · [第一条垂直切片](./health-focus-garden-slice-1.md)

## 1. 已确认的关键决策

1. **不做系统原生通知**，健康提醒使用应用内弹窗，复用现有悬浮卡片的视觉语言。
2. **提醒状态全部落 DB**，进程内只保留一个 20 秒心跳，不维护 per-rule 定时器。
3. **新功能全部新表**，可以放在同一个 `tasks.db`，迁移版本升到 v7。
4. 间隔最小 **10 分钟**，支持 10 / 20 / 30 / 45 / 60 / 90 与自定义 10 分钟步进。
5. 间隔锚点可选：**从创建时刻起算** 或 **对齐整点**。
6. 有效专注单次 **+1 成长值**，每日上限 **10 次**。
7. 喝水 **+2 成长值/滴**，每日 **3 滴**；起身 **+2 成长值/阳光**，每日 **3 个**。
8. 植物成熟线 **15 成长值**，超出部分不结转。
9. 成长日按行为判定：**1 次有效专注** 或 **2 次健康确认**。
10. 植物改为 **一株一循环**：种子 → 生长 → 成熟 → 产种子 → 再种植；不再强制每天一株。
11. 待领取奖励在 **菜单栏下拉面板** 和 **侧栏工具导航** 显示数字，不发通知、不计入任务角标。
12. V1 不暴露本地 API / MCP 的新工具数据。

## 2. 健康提醒

### 2.1 弹窗形态

- 新窗口 `reminderPopupWindow`，尺寸约 `420×96`，随内容最高增至 140。
- 固定在主屏右下角，始终置顶、不占任务栏、可拖动。
- 使用 `showInactive()`，不抢焦点。
- 同一时刻只显示一个弹窗；同一分钟到期的多条规则合并为一个弹窗，每行一个确认动作。
- 队列最多 3 条；超出时最旧的直接过期，避免休眠恢复后连续弹窗。
- 45 秒无操作自动过期，不奖励、不重复弹。
- 应用重启后，10 分钟内的 `pending` 实例可以重新显示；更早的过期。
- 音效复用现有 `notificationSound` 配置；专注进行中默认静音，只显示弹窗。

### 2.2 调度

进程内只有一个 20 秒心跳：

1. 查询 `reminder_rules` 中 `enabled=1 AND next_run_at <= now` 的规则。
2. 若 `now - next_run_at <= 90 秒`，创建或复用 occurrence 并弹窗；超过 90 秒视为错过，不补发。
3. 计算并写回 `next_run_at`。
4. 处理 `snoozed_until <= now` 的实例。
5. 清理 30 天前的 occurrence 和过期队列。

启动、系统唤醒、规则修改时，只从 DB 重算 `next_run_at`；不需要 `node-schedule` 的 per-rule job。

### 2.3 间隔与锚点

规则字段：`anchor_mode = created | hour`，`anchor_minutes = 当日分钟数`。

- **created**：锚点为创建时刻，首次触发 = 锚点 + 一个间隔。
- **hour**：锚点为当前整点向下取整，首次触发 = 锚点 + 一个间隔（即下一个整点）。

示例（窗口 09:00–18:00，间隔 60 分钟）：

| 创建时间 | 模式 | 触发 |
| --- | --- | --- |
| 08:40 | created | 09:40, 10:40 … 17:40 |
| 08:40 | hour | 09:00, 10:00 … 17:00 |
| 10:20 | created | 11:20, 12:20 … |
| 10:20 | hour | 11:00, 12:00 … |

规则：

- 窗口按 `[start, end)` 处理，结束时刻不触发。
- 每天从锚点分钟数重新排槽，避免窗口变化后漂移。
- 修改间隔或锚点模式时，锚点重置为当前时刻 / 当前整点，不补发。
- 暂停恢复后，只在 `pause_until` 之后的第一个槽位触发。
- 夏令时不存在时刻跳过，重复时刻只触发一次。
- 10 分钟间隔时，设置页提示“每天最多约 54 次/规则”；成长上限独立计算。

### 2.4 实例状态

`pending → confirmed / snoozed → pending / skipped / expired`

- “稍后”固定 10 分钟，最多 2 次；第 3 次只能确认或跳过。
- 若下一计划槽落在稍后窗口内，跳过该槽，避免同分钟重复弹窗。
- 同一 `rule_id + scheduled_at` 唯一。
- 只有实际弹出或稍后的实例才写入 occurrence；被队列抑制、休眠错过的槽位不落库。
- 确认写入 `activity_events`，`dedupe_key = health:<occurrence_id>:confirmed`，保证只加一次成长值。

### 2.5 提醒类型与资源

| 规则类型 | 确认产出 | 每日上限 | 每日成长 |
| --- | --- | ---: | ---: |
| 喝水 | 水滴 +2 | 3 | 6 |
| 起身活动 | 阳光 +2 | 3 | 6 |
| 休息眼睛（可选） | 无 | — | 0 |

护眼提醒 V1 只提醒、不产资源，避免引入第三种货币。

## 3. 番茄专注

- 主进程持有 `focus_sessions`，渲染层只负责显示。
- 计时基于绝对时间 `ends_at`，不依赖每秒累加。
- 有效专注：用户主动启动、目标时长 ≥15 分钟、正常完成。
- 单次成长值 **+1**，每日前 **10 次**计分；超出的完成仍进历史，成长值为 0。
- 暂停期间不计入有效时长；完成番茄钟不修改任务状态、不写 `tasks` 表。
- 从 Task 发起时可关联 `linked_task_id`，但只是普通字段，不建立外键。
- `powerMonitor` 检测休眠：休眠期间暂停计时，唤醒后顺延 `ends_at`，睡眠不计入专注。
- 应用退出时仍在运行的会话，下次启动标记为 `interrupted`，不发奖励，保留历史。
- 每次有效专注完成后自动进入 **5 分钟休息**；休息可暂停、提前跳过，也可直接开始下一轮专注。
- 休息阶段不产生成长值。

## 4. 成长经济

### 4.1 每日资源

| 行为 | 资源 | 单次成长 | 每日上限 | 每日成长上限 |
| --- | --- | ---: | ---: | ---: |
| 有效专注 | 成长值 | +1 | 10 次 | 10 |
| 喝水确认 | 水滴 | +2 | 3 滴 | 6 |
| 起身确认 | 阳光 | +2 | 3 个 | 6 |
| 护眼 / 延后 / 跳过 / 过期 | 无 | 0 | — | 0 |

- 每日理论成长上限：**22**。
- 水滴、阳光即时结算，不囤积。
- 超过每日上限后，提醒照常，成长值为 0，行为仍进入统计。

### 4.2 成长日

有效成长日满足任一条件：

- 当天完成 **1 次有效专注**；
- 当天完成 **2 次健康确认**（水滴 + 阳光合计）。

只有 1 次健康确认不算。成长日按本地自然日归属，用于连续天数、累计天数和扩建。

### 4.3 植物阶段

| 累计成长值 | 阶段 |
| ---: | --- |
| 0–4 | 种子 |
| 5–9 | 发芽 |
| 10–14 | 幼苗 |
| ≥15 | 成熟 |

- 成熟后产出 1 枚同物种种子，树进入永久收藏。
- 超出 15 的部分不结转。
- 标准日 7 分：第 3 天成熟；重度日 22 分：当天成熟。

### 4.4 种子与物种

| 来源 | 内容 |
| --- | --- |
| 初始 | 物种 1 + 1 枚种子，自动种下 |
| 树成熟 | 同物种种子 ×1 |
| 5 个里程碑 | 各解锁 1 个新物种，并给 1 枚该物种种子 |
| 其余里程碑 | 家具、装饰、宠物、特殊树 |
| 断种保护 | 无种子且无生长中植物时，可领取 1 枚基础种子，不产生成长值 |

- 种子是消耗品；物种解锁永久保留。
- 自动种植默认开启：成熟后自动消耗 1 枚种子种下一株；无种子时暂停并提示。
- 一株一循环，不强制每天一株；植物可以跨天生长，不枯萎、不扣分。
- 没有生长中植物时，专注和健康仍计入成长日与历史，但不增加植物成长值。

### 4.5 一年节奏

标准节奏按 **1 次专注 + 3 次健康确认/天 = 7 成长值/天**：

| 节奏 | 每日成长值 | 约几天一棵 | 300 天约几棵 |
| --- | ---: | ---: | ---: |
| 轻度（2 次健康） | 4 | 4 天 | 75 棵 |
| 标准（1 专注 + 3 健康） | 7 | 3 天 | 100 棵 |
| 健康为主（3 水滴 + 3 阳光） | 12 | 2 天 | 150 棵 |
| 重度（10 专注 + 6 健康） | 22 | 1 天 | 300 棵 |
| 只做专注（1 次/天） | 1 | 15 天 | 20 棵 |

- 成长日是 V1 内容的总闸门，重度用户也不能大幅提前完成徽章与扩建。
- 树的数量可以超过小院容量，超出部分进入历史收藏。

### 5.3 领取规则

- 固定奖励（徽章、扩建、物种、皮肤）达标即生效。
- 物品自选产生永久待领取记录；不通知、不打断、不计入任务角标。
- 候选从当前未拥有的同档次物品中取 `min(3, 剩余数)`；最后一件只剩 1 个候选，直接领取。
- 多笔待领取同时存在时，每次领取前重新过滤已拥有物品。
- 全部物品拥有后，回退为可堆叠的“园艺纪念”装饰；V1 正常流程不会触发。
- 一次解锁只能领取一次；`reward_claims.unlock_id` 唯一。

## 6. Moli 小院

### 6.1 扩建

| 等级 | 区域 | 容量（格） | 连续成长日 | 或累计成长日 | 标准日 |
| --- | --- | ---: | ---: | ---: | ---: |
| Lv.1 | 初始庭院 | 6 | — | — | 0 |
| Lv.2 | 右侧花圃 | 10 | 10 | 15 | 10–15 |
| Lv.3 | 后院林地 | 16 | 30 | 45 | 30–45 |
| Lv.4 | 草坪围栏 | 24 | 90 | 120 | 90–120 |
| Lv.5 | 池塘广场 | 32 | 180 | 270 | 180–270 |

- 惰性结算：写入成长日时检查，不依赖午夜定时任务。
- 连续定义：最后成长日为昨天则 +1，为今天不变，更早则重置为 1。
- 双通道为“或”，任一满足即解锁；解锁永久保留。
- Lv.2–Lv.5 各给 1 枚扩建徽章 + 1 次物品自选。
- Lv.1 为初始状态，不发奖励。

### 6.2 容量与摆放

- 小院是连续的可摆放地块，物品可以放在地块内任意位置，不再绑定固定槽位。
- 容量单位为“件”，Lv.1–Lv.5 分别允许 4 / 10 / 16 / 24 / 32 件。
- 物品尺寸为 `1×1`、`2×2`、`3×3`，尺寸用于边界与碰撞，不再按格子占位。
- 新物品优先落到预设模板位置；位置被占用时自动寻找最近的空位。
- 模板为完整花园预设：小屋、座椅、桌子、花盆、灯、树和宠物各有默认位置。
- 自动摆放默认开启，只处理新获得的物品，不覆盖已摆放物品；关闭后进入收藏。
- 整理模式支持直接拖动物品调整位置，也可以收起物品；拖动和收纳都保留所有权。
- 宠物使用独立容量：Lv.1–3 最多 2 只，Lv.4–5 最多 3 只。
- 未拥有的物品只出现在收藏图鉴中，不会出现在场景或添加托盘里。
- 每日植物和成熟树不占用固定槽位；成熟树作为收藏物品参与自由摆放。

## 7. 导航与待领取

### 7.1 侧栏

```
任务
  今日 / 已安排 / 进行中 / 暂停 / 全部 / 收件箱 / 已完成
工具
  健康提醒
  番茄专注
  Moli 小院   [n]
清单
  ...
```

- 不采用顶部双 Tab，避免与现有透明标题栏和最小窗口宽度冲突。
- 待领取数字只显示在“Moli 小院”；工具分组折叠时显示在“工具”父项。
- 数字是待领取奖励数，不是未读消息；不发红点、不发通知。
- 选中工具时任务状态和筛选保持不变。

### 7.2 菜单栏下拉面板

在现有日历下方增加一行：

```
Moli 小院    n
```

点击打开主窗口小院页并定位到待领取。专注进行中时可显示“专注中 mm:ss”，作为增强项。

### 7.3 不做

- 不做托盘图标数字角标。
- 不做 Dock 数字角标。
- 不把待领取计入任务角标或任务完成率。

## 8. 数据模型

### 8.1 新增表

| 表 | 关键字段 / 约束 |
| --- | --- |
| `reminder_rules` | `type`, `interval_minutes`, `anchor_mode`, `anchor_minutes`, `weekdays`, `window_start`, `window_end`, `enabled`, `pause_until`, `next_run_at`；`next_run_at` 索引 |
| `reminder_occurrences` | `rule_id`, `scheduled_at`, `status`, `snoozed_until`, `snooze_count`, `responded_at`, `local_date`；`UNIQUE(rule_id, scheduled_at)` |
| `focus_sessions` | `linked_task_id`（普通字段）, `planned_seconds`, `focus_seconds`, `status`, `started_at`, `ended_at`, `paused_ms` |
| `activity_events` | `dedupe_key` 唯一；`source_type`, `source_id`, `event_type`, `growth_points`, `occurred_at`, `local_date`, `tz_offset` |
| `activity_daily_summary` | `local_date` 主键；`focus_count`, `water_count`, `sun_count`, `total_growth` |
| `plant_instances` | `species_id`, `growth_score`, `stage`, `planted_at`, `matured_at`, `status`, `local_date_planted` |
| `seed_inventory` | `species_id`, `quantity`；`UNIQUE(species_id)` |
| `species_unlocks` | `species_id` 主键、`unlocked_at`、`source` |
| `growth_days` | `local_date` 唯一、`growth_score`、`created_at` |
| `garden_state` | 单行：当前连续、最长连续、累计成长日、等级、`active_plant_id`、自动种植开关 |
| `garden_expansions` | `level` 主键、`unlocked_at`、`condition_type` |
| `milestone_unlocks` | `definition_id` 唯一、`unlocked_at`、`claim_status`、`definition_version` |
| `reward_claims` | `unlock_id` 唯一、`selected_item_id`、`claimed_at` |
| `inventory_items` | `catalog_id`, `kind`, `quantity`, `origin_type`, `origin_id`, `acquired_at`；唯一物品 `UNIQUE(origin_type, origin_id)` |

物品、里程碑、扩建和物种定义使用打包 JSON 配置，带 `catalog_version`；领取记录保存版本号。

### 8.4 导出、导入与清空

- 导出升级到 v3：包含全部新表与 `catalog_version`。
- 导入兼容旧备份；缺少新数据时按空处理。
- “清除所有数据”必须明确包含任务、专注、植物、种子、收藏、徽章与摆放，并进行二次确认。
- 本地 API / MCP 在 V1 不暴露新工具数据。

- 所有业务控件复用 `components/ui`，不在业务组件中重写 Button、Dialog、Dropdown、Checkbox、Switch、Tooltip。
- 新增图标使用本地打包的 Lucide Vue 组件，图标按钮提供可访问名称。
- 五套主题共享布局与交互，通过现有语义 token 表达差异。
- 支持 `prefers-reduced-motion`；小院场景动画可单独关闭。
- 未解锁收藏使用灰色剪影 + 文字条件，不只依赖颜色。
- 弹窗支持键盘：确认、稍后、跳过均可聚焦；关闭后焦点返回原控件。
- 健康提醒页展示今日节律、最近 7 天完成情况、下一次提醒、规则卡片与最近提醒记录；规则创建和编辑使用统一 Dialog。
- 番茄专注页使用大号环形计时器，提供 15/25/45/60 分钟与自定义时长、未完成任务关联、今日统计和最近 7 天记录。
- 提醒弹窗使用独立卡片说明类型、时间和已推迟次数，确认、稍后与跳过保持可聚焦。
- 小院收藏页按年份、物种、未摆放筛选；树数量较大时分页或虚拟滚动。
