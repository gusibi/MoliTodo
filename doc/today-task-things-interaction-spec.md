# Today 单条任务的 Things 式展开交互 Spec

日期：2026-09-25
状态：已实施（2026-09-25）
范围：主窗口 Today 页中间 Agenda 内的一条任务；适用于该区域现有全部分组

## Problem Statement

用户希望在 Today 页像 Things 一样，先浏览简洁的任务，选中某一条后直接围绕它编辑。当前同一条任务的操作分散在三处：标题单击变为输入框；安排和提醒各有行上气泡；备注、步骤、截止、重复、清单等要通过“详情”进入从右侧滑出的编辑面板。面板打开还会收起右侧 Future Calendar。编辑目标在空间上跳走，任务本身没有从浏览态连续变成编辑态，用户需要记忆字段在哪里。

Today 已有的时间、状态、计时、重复实例、步骤和删除能力比 Things 的普通待办更丰富。改造必须降低单条任务的交互碎片感，同时保留这些能力、既有业务语义和其他页面的数据一致性。用户明确要求左侧导航、右侧日历，以及“今天”“明天”“未安排”等现有分组保持存在。

## Solution

Today 的每条任务采用“紧凑浏览态 → 原位展开态”的单一编辑模型。浏览态让标题成为视觉主角，保留必要的状态与时间摘要；单击任务正文或用键盘打开后，该任务在原分组内向下展开。标题、备注、步骤、安排、截止、提醒、重复、清单归属和现有状态动作都能从这块展开内容中触达。用户完成编辑后收起同一条任务，左侧导航、右侧 Future Calendar 和分组结构保持在原位。

展开是一种展示状态，不是“开始一笔待提交的事务”。现有立即保存和字段级自动保存规则继续成立；每个字段清楚反馈成功或失败。快速改期、提醒、开始、暂停、完成等行上捷径继续可用。动效只帮助用户跟踪“这条任务展开、收起或移动到另一分组”，不改变保存或分组时机。

## User Stories

1. As a Today 用户, I want 在每个现有分组中快速扫读任务标题, so that 我能先决定要处理哪一条。
2. As a Today 用户, I want 单击任务正文就在原位置展开它, so that 编辑时不会丢失所在分组的上下文。
3. As a Today 用户, I want 展开任务时左侧导航和右侧日历继续可见, so that 我仍能掌握页面位置和日期。
4. As a Today 用户, I want 同时只展开一条任务, so that 长任务不会把整页变成一组表单。
5. As a Today 用户, I want 在展开态直接修改标题和备注, so that 不必在行内输入框与侧边面板之间切换。
6. As a Today 用户, I want 长标题和长备注能够自然换行与滚动, so that 内容不会被截断或遮住操作。
7. As a Today 用户, I want 收起态仍能识别备注、所属清单、重复和重要时间状态, so that 精简界面不会藏掉已有信息。
8. As a Today 用户, I want 点收起态的日期摘要直接改期, so that 简单顺延无需先展开任务。
9. As a Today 用户, I want 在展开态明确区分“安排开始”“安排结束”和“截止”, so that 我不会把计划时间误当作必须完成的期限。
10. As a Today 用户, I want 快速选择今天、明天、下周、具体日期与清除安排, so that 常见改期足够快。
11. As a 有时段安排的用户, I want 改变开始时间时保留现有时长, so that 结束时间不会意外丢失。
12. As a 有截止任务的用户, I want 保留仅日期或日期加时间两种截止形式, so that 无时刻的截止不会被伪造成午夜时间。
13. As a 有提醒的用户, I want 在展开态设置、修改和清除相对或绝对提醒, so that 复杂提醒能力仍然可用。
14. As a Today 用户, I want 行上的提醒捷径继续可用, so that 小改动不用展开全部内容。
15. As a 有重复任务的用户, I want 在展开态查看和修改重复规则, so that 我不必去另一个视图管理它。
16. As a 重复任务用户, I want 修改单次实例时只影响目标实例, so that 系列模板和其他日期不会被误改。
17. As a 有步骤的用户, I want 展开任务后立即看到现有步骤及完成状态, so that 我能接着做下一步。
18. As a 有步骤的用户, I want 在步骤末尾连续输入并添加新步骤, so that 拆解任务时无需反复点击按钮。
19. As a 有步骤的用户, I want 单击步骤文字编辑、勾选步骤完成, so that 常用操作各只需一次明确动作。
20. As a 有步骤的用户, I want 删除步骤前看到现有的危险确认, so that 不会因为误点直接失去内容。
21. As a 有步骤的用户, I want 步骤保存失败时保留输入并能重试, so that 不会丢失刚写的内容。
22. As a 计时用户, I want 开始、暂停、继续、完成和耗时显示保持可用, so that 任务展开不打断计时流程。
23. As a Today 用户, I want 完成、重做和删除入口保持明确, so that 外观变化不改变这些动作的后果。
24. As a Today 用户, I want 任务改期或完成后自然移动到正确分组并更新计数和日历点, so that 页面与保存结果一致。
25. As a Today 用户, I want 已展开任务移动后还能找到它或收到明确的移动说明, so that 它不会无声消失。
26. As a 键盘用户, I want 用 Enter 打开选中任务、用 Escape 逐层关闭弹层或收起任务, so that 我不依赖鼠标。
27. As a 键盘用户, I want 关闭后焦点回到仍有效的任务或相邻入口, so that 我能继续操作。
28. As a 输入中文的用户, I want 拼音组合期间的 Enter 不误提交, so that 我能正常写标题、备注和步骤。
29. As a 辅助技术用户, I want 展开状态、字段名称、错误和动作后果可被读出, so that 我能理解当前任务状态。
30. As a 减少动态效果的用户, I want 任务展开和移动即时完成, so that 页面不会强制播放动画。
31. As a 窄窗口用户, I want 展开任务仍留在 Agenda 中且不遮挡日历抽屉入口, so that 缩小窗口后仍能编辑。
32. As a 主题用户, I want 五套主题明暗模式下的正文、次级信息和焦点清晰, so that 我能继续使用既有外观。
33. As a 使用其他任务视图的用户, I want 同一任务的数据在列表、日历和悬浮窗同步, so that Today 编辑不会造成不同窗口结果相反。
34. As a 拖拽用户, I want 原有拖到侧边栏清单的行为保留, so that 现有整理方式继续可用。
35. As a 搜索用户, I want 标题和备注高亮、筛选范围继续正确, so that 展开态不会破坏搜索结果。

## Implementation Decisions

### 1. 范围、信息结构与空间关系

- 本次只改变主窗口 Today 的单条任务。Agenda 的收件箱、逾期、待重新安排、今天、明天及后续日期等分组规则和顺序保持现状；侧边导航、Future Calendar、窄窗口日历抽屉保持现状。
- 浏览态仍由任务状态、标题、可选备注预览和元信息组成。标题是一级视觉信息；安排、截止、提醒、清单、重复、耗时、分组原因作为次级信息。重要状态不能只靠颜色表示。已有字段不删除，只允许通过更轻的样式、摘要或展开态展示降低噪声。
- 展开态嵌在原任务行所在的 Agenda 分组内，由内容推开后续任务。它不覆盖日历、不把日历收起、不把整条任务移动到右侧面板。展开后保持任务标题在可视区域；内容过高时由 Agenda 正常滚动，不创建另一个长距离嵌套滚动区域。
- 一次只展开一条。打开另一条前，先完成当前字段按既有规则应执行的保存；若保存失败，保留当前展开态和失败草稿，不直接切换。
- 用户点击任务正文或标题打开；点击状态、日期、提醒等明确动作只执行该动作，不顺带展开。浏览态不显示单独的展开箭头或删除按钮；标题本身可直接编辑。
- 浏览态的状态圆圈维持当前“状态展示”语义；开始、暂停、继续、完成、重做维持当前明确的动作按钮。不要把圆圈改成另一套可点击状态机，也不要删除计时能力。

### 2. 展开态布局与字段归属

- 展开内容从上到下依次为：标题和当前状态；备注；步骤清单及添加入口；任务属性区；低频操作区。空备注和空步骤清单用简洁的添加入口表示，不保留大片空白。
- 任务属性区必须提供当前已有能力：所属清单、安排开始及结束、截止日期及可选时间、提醒策略及时间、重复规则。属性采用轻量入口，当前值可见；点击后打开对应 Popover、日期选择器或已有规则编辑器。不能为了“像 Things”而合并或删除这些不同字段。
- Today 展开态在宽度足够时将安排开始与结束并排，截止与重复并排；未设置安排开始时继续隐藏结束入口。窄宽度下成组纵向排列，其他任务编辑场景沿用原有纵向布局。
- 开始、结束、截止、提醒各用准确文案。安排回答“何时做”，截止回答“何时前完成”，提醒回答“何时通知”。现有时间模型、时区、日期型值、提醒重算与警告逻辑沿用应用层规则。
- 任务所属清单继续可改，成功后与其他视图同步。移动清单不改变 Today 分组语义，除非已有业务规则会使其变化。
- 低频操作保留删除任务及其他当前编辑器实际可达的动作。浏览态删除放在任务右键菜单，键盘可用 Shift+F10 打开；删除继续走统一 AlertDialog，文案说明移入垃圾桶及现有恢复方式；取消无副作用，提交中防重复，失败保留上下文。
- 当前独立编辑器仍供其他页面及新建流程使用；Today 的展开态应复用已有业务逻辑和基础组件，但不把整块旧面板原样塞入任务行。避免两套 Today 编辑入口同时存在，造成字段和保存行为漂移。

### 3. 文本编辑与保存契约

- 展开态的标题、备注采用现有字段级自动保存/失焦提交语义；步骤的新增、修改、完成、删除和时间属性按各自动作提交。不提供暗示可一次性撤销全部已保存字段的“取消整个编辑”按钮。
- 打开任务本身是只读 UI 状态切换，不写数据库。鼠标点标题打开时光标进入标题；键盘选中任务后按 Enter 打开时焦点进入标题。不得因为打开虚拟重复实例就立即物化；首次真实修改时才按既有单次实例规则处理。
- 标题不能为空。文本输入期间 Escape 先放弃当前字段尚未成功保存的草稿并恢复已保存值；再次 Escape 收起任务。失焦或显式收起时先保存有效草稿，保存成功后收起。中文输入法组合期间的 Enter 不触发保存或新步骤。
- 备注允许清空。自动保存和失焦保存使用同一最终值，避免迟到的防抖请求覆盖较新的值。切换任务、改期导致任务移动、删除或关闭窗口时，应取消过期定时器并完成或妥善保留尚未提交的输入。
- 每次写入检查现有 store/API 返回的成功标记。失败时保留原输入、显示与字段相邻的可理解错误及重试动作，不只写控制台；不把失败值当作已保存值展示。提交中的字段避免重复提交。
- 备注和步骤都位于任务 metadata。它们的并发保存不能用过期的整份 metadata 覆盖彼此；写入时应基于最新任务元数据，只提交目标字段或由既有应用服务正确合并。不得为本需求引入新的数据库结构或独立步骤实体。

### 4. 日期、提醒和分组迁移

- 浏览态现有 When chip 与提醒 pill 保持快捷入口。展开态的安排与提醒入口调用同一套业务动作；不得出现两种结果不同的“明天”或“清除安排”。
- When 快捷项继续包含今天、明天、下周、清除和具体日期/时刻。改变已有开始时间且原来存在有效结束时间时，按原时长平移结束时间；手动编辑结束时间时仍允许修改或清除。
- 截止仍单独编辑，支持仅日期、日期加时间、清除时间和清除截止。过去安排不等同于截止逾期，计时超时也不是截止逾期。当前只有截止、没有安排的任务不能因为清除安排而丢失截止。
- 提醒继续支持既有相对、绝对、禁用/清除策略及预设；与安排变化相关的重算由现有业务层执行，不在 UI 另写日期算法。
- 保存日期后由现有 Agenda 模型决定任务在哪个分组，计数与 Future Calendar 点同步。若目标分组已在当前 Agenda，展开态跟随同一任务身份到新位置并滚动到可见；若目标因当前过滤或加载范围不在视图中，则收起并给出明确的目标日期/分组反馈，焦点落在原位置附近仍有效的控件。
- 所有显示与定位逻辑使用当前任务的稳定身份，重复任务要区分系列和单次实例；不得靠列表索引在任务移动后指向另一条任务。

### 5. 步骤清单

- 展开时读取现有步骤及状态。每行包含完成控件、可单击编辑的内容和删除入口；完成态保留可辨认的文字/图标语义。完成步骤引发任务自动进入进行中等现有业务规则继续有效。
- 清单末尾始终有“添加步骤”输入位。输入非空时 Enter 创建并保持焦点在下一条空输入位；空输入按 Enter 不创建。粘贴多行文本时逐行生成步骤是增强项，仅在既有行为支持时保留，不作为本次新增验收门槛。
- 单击步骤正文进入输入；Enter 保存，Escape 放弃未保存草稿，失焦保存有效内容。空白内容不得覆盖已有步骤；失败时保持编辑态与输入。步骤切换完成失败时恢复旧状态并显示错误。
- 删除步骤仍走项目现有 AlertDialog 契约。取消保留步骤；确认成功后才从界面移除；失败保留步骤、显示错误并允许重试；确认和关闭后焦点回到相邻步骤或添加入口。不要因为追求流畅把危险删除改成无确认且没有等价恢复保障的动作。
- 步骤顺序保留。此轮不新增排序能力；现有其他视图若有排序操作，Today 编辑不能把顺序重置。

### 6. 动效、焦点与无障碍

- 展开/收起表现为同一任务表面连续改变大小、内容渐入渐出、下方任务自然让位。建议展开 180–240ms、收起 140–200ms，使用现有共享动效规则和 ease-out 类曲线；数值是视觉验收起点，不是业务定时器。动画结束前不延迟保存、分组或点击响应。
- 任务因完成、删除或改期离开分组时，先以轻微位移/淡出表示目标离开，再由列表补位；若数据立即更新，使用布局过渡保持位置连续。不要使用旋转、弹跳、长时间脉冲或每个元信息各自飞入。
- Popover/日期选择器是最上层时，Escape 先关闭它并将焦点还给触发器；其后 Escape 才处理当前输入草稿或收起任务。AlertDialog 遵守已有提交中、取消及焦点恢复规则。点击窗口外时先提交有效草稿，再收起；点击其他任务按“先保存再切换”处理。
- 任务展开触发器可聚焦，有可访问名称及 `aria-expanded`；各字段、步骤和图标按钮有明确标签与状态；错误通过可感知文本和适当状态通知呈现。hover 才显示的次要操作在 focus-within 和弹层打开时也可见，出现时不挤动标题。
- `prefers-reduced-motion: reduce` 时取消非必要过渡和位移动画，功能、焦点顺序与保存结果不变。五套主题的明暗模式共用同一布局与交互。

### 7. 模块职责与实施顺序

- Today 页面协调层只保存“当前展开的是哪条任务”、焦点/滚动锚点以及现有日历与分组状态；任务内容来自现有 store 和 Agenda 模型，不复制一份长期不同步的任务对象。
- Today 任务行负责浏览态、展开态和字段组合；When、提醒、状态、基础按钮、Popover、AlertDialog 先查现有 `components/ui` 与共享业务组件，缺能力时在基础层补齐，再由任务行组合。UI 不直接操作 SQLite。
- 先完成单条任务展开和标题/备注保存，再接入步骤和所有属性入口，之后接入任务跨分组移动、动效、键盘与视觉收尾。每阶段保持真实任务链路可运行，避免先做静态壳再补业务。
- 不要求改数据库、任务状态机或全项目 TypeScript。只有现有 store/API 无法安全完成某个字段更新时，才对该业务边界做最小修正。

## Testing Decisions

### 测试接缝

- 主要且优先的测试接缝是现有 Playwright Electron Today E2E：真实渲染层、IPC、应用服务和隔离 SQLite。使用既有 fixture、独立用户目录和串行执行；断言用户可见结果和持久化数据，不断言内部组件名称、ref、动画实现或某个 CSS 类。
- 复用现有 Today 关于日期分组、日历点、标题编辑、When/提醒气泡、开始暂停完成、虚拟重复实例、删除、窄窗口和减少动态效果的用例；更新旧用例的入口预期。步骤确认流程已有任务视图 E2E，可沿用该场景设计，不另建模拟数据库。
- 只有在并发 metadata 保存或日期型值规则出现可复现回归时，才在现有服务/纯函数边界补对应单元测试。优先保持一个端到端测试入口，不为了 UI 拆出大量新测试缝。

### 必须覆盖的验收场景

1. 在收件箱、今天、明天和后续日期分组中打开、切换、收起任务；右侧日历与左侧导航始终可用，只有一条任务展开。
2. 鼠标及键盘编辑标题、备注；空标题被阻止；输入法组合不误提交；Escape 放弃未保存字段草稿，再次 Escape 收起；重启后已保存内容存在。
3. 浏览态及展开态分别改安排、结束、截止和提醒；日期型截止不变午夜时间戳；改开始保留有效时长；清除安排不清除截止；计数与日历点同步。
4. 添加、连续添加、编辑、完成、取消完成、取消删除、确认删除和删除失败重试步骤；完成步骤后的任务状态符合既有规则，重启后步骤内容与顺序存在。
5. 编辑虚拟重复实例的标题、日期和步骤时仅目标实例变化，无重复任务卡片，系列模板和其他实例不受影响。
6. 开始、暂停、继续、完成、重做、计时显示、软删除及垃圾桶恢复仍正确；悬浮窗与普通列表看到同一数据。
7. 日期修改让展开任务进入另一可见分组时，仍能定位同一任务；目标不在当前范围时有明确反馈；焦点不落在被移除的节点。
8. Popover、日期选择器、步骤确认和任务删除确认的 Escape 顺序、焦点恢复及提交中防重复正确；单击行上快捷按钮不误展开。
9. 长中英文标题、较多步骤、窄窗口、五套主题明暗模式及减少动态效果下可完成同样操作，正文、焦点和错误状态可读。
10. 原有搜索高亮、拖拽到侧边清单、其他页面编辑器和新建任务流程没有行为回归。

## Out of Scope

- 改造 Sidebar、Future Calendar、Today 的分组算法、主窗口 Header、普通列表、看板、月历或悬浮窗的任务外观。
- 把所有页面统一迁移到原位展开；其他页面的既有编辑器与新建流程保持可用。
- 新的任务字段、数据库表、任务类型、提醒策略或重复规则。
- 新的全局快捷键体系、命令面板、步骤排序功能或跨窗口浮层框架。
- 完全复制 Things 的配色、文案和功能取舍；MoliTodo 既有状态、计时、安排结束、提醒和重复能力必须保留。
- 用无确认的删除加临时撤销替换项目现有步骤/任务危险确认流程。

## Further Notes

- 本 Spec 承接已实现的 Today Agenda 与任务行基础能力。先前的 #15 明确把低频字段留在右侧编辑面板，并排除 Today 步骤展示；本次用户请求扩大了单条任务交互范围，因此本 Spec 对 Today 的这两项决策具有优先级。#15 的业务规则、When/提醒捷径、状态动作、软删除和测试结论仍应复用。
- 现有 Today 测试把“打开编辑器时收起日历”视为预期；实施时应将其改成“展开任务时日历保持可见”。旧测试失败不能简单删除，必须以新验收场景替代。
- 当前步骤存于任务 metadata，标题/备注存在自动保存，任务时间又有安排、截止、提醒等不同语义。这些差异是实现时最容易丢功能或覆盖数据的地方，视觉精简不能抹掉字段边界。
- 测试接缝建议沿用项目现有 Electron Today E2E，供用户审阅；本技能要求不进行访谈，因此不以等待额外确认阻断规格交付。
